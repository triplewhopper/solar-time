# 本地太阳时计算器

静态网页，在浏览器本地计算平太阳时、真太阳时与 UTC+9 的差值。
不调用计算 API，不上传或保存输入坐标。可手动输入，也可点击“使用当前位置”请求浏览器单次定位并填写经纬度。
这是现代天文模型的独立实现，不是 Horizons 官方程序，也不保证与其逐位一致。

## 发布方式

GitHub Pages：main 分支，发布目录 /(root)，Deploy from a branch。
根目录已有 index.html 和 .nojekyll。数据更新由 Actions 定时任务执行；网页仍按 main 根目录发布，无需计算服务器或数据库。
GitHub 自己执行的 Pages 构建/部署任务属于平台内部流程。

## 输入范围

| 参数 | 范围 |
|---|---|
| 经度 | −180° 至 +180°（含端点） |
| 纬度 | −90° 至 +90°（不含端点） |
| 用户填写的海拔 | −1000 至 100000 米 |
| 日期，UTC+9 | 1972-01-01 09:15:00 至 2099-12-31 23:59:59.999 |
| 度分秒 | 度、分为整数；分在0–59；秒在[0,60)，可带小数 |
| 时间 | 毫秒输入；不支持直接输入23:59:60标签 |

日期范围是计算器的硬边界，首日预留太阳光行时。自动计算还须落在所选EOP数据覆盖区间内。
JPL数据以TAI为时间轴，IERS数据以UTC为时间轴；两者不可直接混用时间标签。
默认不外推。高级设置可显式启用JPL固定末值外推，但这不保证未来实际太阳时准确。
手动参数范围：DUT1±10秒，xp/yp±10角秒，dX/dY±1000毫角秒，TAI−UTC为10至100的整数秒。
另外测试了52,596个原始SPK记录边界及前后1微秒的星历位置和速度。

这些是数值输入界限，不是对这些参数物理正确性的保证。

## 算法与数据

- 原始JPL DE441 SPK Type2系数；太阳 (0,10)，地球 (0,3)+(3,399)。
- UTC→TAI→TT→TDB；UT1由DUT1求得；使用双部分儒略日。
- ERFA（SOFA派生库）：默认IAU1976/1980，现代备选模式IAU2006/2000A；极移、WGS84站点位置与速度。
- 迭代光行时、轨道及自转光行差、站点视差；太阳中心、无大气折射。
- 太阳当地视时角来自同一参考系内的站点子午面与太阳视赤经之差；真太阳时为12小时加时角。
- 默认使用经过独立验证的最新原始/PCK快照、ITRF93和IAU1976/1980；原始格式及现代JPL/IERS备选模式保留。
- Horizons文档采用ITRF93、修正的IAU1976/1980及其legacy EOP；现代JPL/IERS备选模式与之约定不同。

地球自转数据冻结在明确标注的日期。未来闰秒与新的测量数据需要更新。
所有来源、哈希、实测差异及未解决项见网站的“验证报告”和 data/provenance.json。
保留 vendor/ 中的ERFA许可。DE441数据来源于NASA/JPL公开发布。

## 验证

运行 node tests/full-domain.cjs、node tests/legacy-tests.cjs、node tests/spk-boundaries.cjs，再运行 python3 scripts/report.py。
此命令离线重放113,524个原生ERFA/jplephem参考案例和42,200个已缓存Horizons案例，包含：

- 每日覆盖20,044天；所有所选SPK分段边界的58,440个邻域点。
- 32,768个固定随机种子的独立样本，224个输入角点，2,048个人工EOP极值压力样本。
- 40个全球、近极、经度边界、高度边界和随机保留地点，各1,055个历史/预测/未来时刻。
- 无效输入、日期边界、±180°等价性、所有数据内闰秒事件、外推必须显式启用等检查。

有限测试不能穷尽连续输入空间，也不是全域误差上界证明。
接近两极时子午面病态，极移与参考框架的微小差别会被放大到秒、分钟甚至更大；页面明确警示。
同模型的原生库一致性验证只检查数值实现，不能证明模型等于物理真值。

- tests/generate-native-domain.py 使用 numpy、pyerfa、jplephem 重新生成原生参考。
- tests/capture-domain.py 仅供维护者重新采集对照：串行、批量、缓存的人工坐标查询，不属于网页运行路径。
- scripts/report.py 重建可读报告，不会生成压缩下载包。

## PCK恢复快照与验证

最初研究时公开ASCII镜像仍是11月17日，因此独立恢复了11月18日参数。2026-11-19 后续检查已取得11月18日原始文件，137条恢复记录与原件逐项一致；当前版本见 data/runtime.json。
从官方 earth_000101_270214_261118.bpc 独立恢复2026-10-01至2027-02-14的137条日记录，其余历史记录保留原始11月17日文件。
恢复仅使用PCK旋转矩阵，不用Horizons太阳时残差拟合；随后才用独立Horizons输出验证。

- 70个重叠窗口，零记录冲突；已知历史32条/160个字段按原精度恢复全部一致。
- 544个未参与恢复的PCK时刻检查。
- 42,200组独立Horizons对照：全体最大差异约3.082微秒，含近极区、预测和固定末值外推。
- 32个末端检查：最大差异约0.625微秒。2月14日记录保留作插值支撑，但2月13日起固定参数。
- 每种模型各113,524组独立原生库参考检查；52,596组星历记录边界检查。

上述固定回归用的恢复快照不是原始文件下载副本；当前原件状态另见版本记录。这些统计不是全域误差上界或未来实际地球自转精度的证明。

复现数值检查：

    node tests/full-domain.cjs
    node tests/legacy-tests.cjs
    node tests/legacy-tests.cjs --reconstructed
    node tests/reconstruction-tests.cjs
    node tests/spk-boundaries.cjs
    python3 scripts/report.py

恢复数据的独立复现：先在虚拟环境安装 numpy、pyerfa、jplephem、skyfield、certifi，再运行 research/pck/reproduce.py。
该脚本仅下载固定哈希的官方PCK文件，不调用Horizons；生成物写入被Git忽略的scratch目录。

来源、校验值、失败的单窗口边界诊断和最终重叠窗口验证均保存在数据与测试记录中。

## 自动更新（GitHub Actions）

`.github/workflows/update-eop.yml` 每天 UTC 19:37（东九区次日 04:37）检查，也可手动 Run workflow；算法、输入逻辑、验证脚本及测试文件改动会通过 push 自动触发检查。是否跑完整回归取决于数据哈希和 `data/regression-state.json` 中上次通过的算法指纹。
GitHub 定时任务可能延迟；不是秒级调度。无需 Mac 开机，不需要另配个人访问令牌。

1. 先下载并比较官方文件哈希，同时比较上次成功验证的算法指纹。数据和算法都未变时，跳过数值依赖安装、完整回归及候选重算。
2. 有新数据或算法变化时，用 `tests/snapshots/2026-11-18/eop.json.gz` 与原有 Horizons 缓存做完整固定版本回归，再验证预检查时下载的同一份候选数据。无变化直接成功结束，不修改文件、不提交、不发布。
3. 有变化时重新恢复 PCK 参数；如果同版本原件已公开，逐项确认恢复记录与原件一致后优先采用原件。
4. 新版本用独立原生库检查 113,524 组，并串行查询六个**人工地点**的同版本 Horizons 参考，包含恢复区间每日点、预测末端及极区。版本不同、冲突或超过 10 微秒门槛均不发布。
5. 提交通过验证的数据到 main，再调用 Pages build API 并确认该提交构建成功。仍为 `Deploy from a branch: main /`。

网页加载时核对数据 SHA256，打开期间每五分钟及切回页面时检查版本；切换数据保留用户输入。太阳时仍完全在浏览器内计算。
`data/runtime.json` 为当前版本，`data/update-status.json` 为上次发布时的检查记录；无变化的检查时间只保存在 Actions 运行记录中。Actions 红色失败记录表示后续检查失败，页面继续用上次已验证数据。
`validation.html` 的 42,200 组统计固定属于 2026-11-18，不冒充新版本测试。每次新版本的独立结果在 `data/releases/`，网页保留最近 30 个发布快照，更早记录留在 Git 历史。
完整候选（包括失败）的审核数据作为 Actions artifact 保留 14 天。

自动化仅维护默认的原始/PCK快照及其ASCII基准；现代EOP2/IERS备选模式仍是标注版本的固定数据。
遇到新闰秒、上游格式/模型改变、原始镜像/PCK/Horizons版本不同或恢复检查失败，会中止更新，需要维护后再继续；不会放宽阈值掩盖问题。

本地试跑：

    python -m pip install -r scripts/update-requirements.txt
    python scripts/update-eop.py --force --dry-run

`--dry-run` 不修改线上数据文件。每天更新无需重复下载或更换DE441星历、ERFA算法。

## 海拔输入

表单只填写海拔（米），可直接录入 iPhone 罗盘读数。前端加载 GeographicLib 发布的 EGM2008 5分网格，在浏览器本地双线性插值计算 N，再以 h=H+N 转换给天文引擎。全球网格整体加载并缓存，不发送用户位置查询。原始网格及压缩文件的校验值见 data/geoid.json。
天文核心API的 height 仍为内部椭球高；geoidUndulation 用于将输入范围校验对应到海拔。原有天文回归测试继续使用已固定的内部高度。海拔层单独由 tests/geoid-tests.cjs 检查。

## 单次定位

“使用当前位置”仅在点击时调用一次 getCurrentPosition（高精度请求、15秒超时、不复用旧定位），不使用持续跟踪。开始定位即清空海拔和旧结果。成功后填入经纬度；只有浏览器返回有效 altitude 与 altitudeAccuracy 才把 WGS84 高度减去 EGM2008 的 N，填入海拔后计算。未取得有效高度时海拔留空，等待手动填写，绝不以 0 替代缺失值。拒绝、超时或不可用时可重试或手填；定位等待期间编辑坐标或海拔、填示例或清空，会使该次晚到的结果失效。位置权限是否被记住由浏览器管理。
