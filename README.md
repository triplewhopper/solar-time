# 本地太阳时计算器

静态网页，在浏览器本地计算平太阳时、真太阳时与 UTC+9 的差值。
不调用计算 API，不请求 GPS 权限，不上传或保存输入坐标。
这是现代天文模型的独立实现，不是 Horizons 官方程序，也不保证与其逐位一致。

## 发布方式

GitHub Pages：main 分支，发布目录 /(root)，Deploy from a branch。
根目录已有 index.html 和 .nojekyll。无需自行编写 Actions 工作流，无需服务器、数据库或构建依赖。
GitHub 自己执行的 Pages 构建/部署任务属于平台内部流程。

## 输入范围

| 参数 | 范围 |
|---|---|
| 经度 | −180° 至 +180°（含端点） |
| 纬度 | −90° 至 +90°（不含端点） |
| WGS84 椭球高 | −1000 至 100000 米 |
| 日期，UTC+9 | 1972-01-01 09:15:00 至 2099-12-31 23:59:59.999 |
| 度分秒 | 度、分为整数；分在0–59；秒在[0,60)，可带小数 |
| 时间 | 毫秒输入；不支持直接输入23:59:60标签 |

日期范围是计算器的硬边界，首日预留太阳光行时。自动计算还须落在所选EOP数据覆盖区间内。
JPL数据以TAI为时间轴，IERS数据以UTC为时间轴；两者不可直接混用时间标签。
默认不外推。高级设置可显式启用JPL固定末值外推，但这不保证未来实际太阳时准确。
手动参数范围：DUT1±10秒，xp/yp±10角秒，dX/dY±1000毫角秒，TAI−UTC为10至100的整数秒。
另外测试了52,596个原始SPK记录边界及前后1微秒的星历位置和速度。

这些是数值输入界限，不是对这些参数物理正确性的保证。

## 算法与数据

- 原始JPL DE441 SPK Type2系数；太阳 (0,10)，地球 (0,3)+(3,399)。
- UTC→TAI→TT→TDB；UT1由DUT1求得；使用双部分儒略日。
- ERFA（SOFA派生库）：默认IAU1976/1980，现代备选模式IAU2006/2000A；极移、WGS84站点位置与速度。
- 迭代光行时、轨道及自转光行差、站点视差；太阳中心、无大气折射。
- 太阳当地视时角来自同一参考系内的站点子午面与太阳视赤经之差；真太阳时为12小时加时角。
- 默认使用明确标注的PCK恢复快照（2026-11-18等价参数）、ITRF93和IAU1976/1980；原始11月17日及现代JPL/IERS模式保留。
- Horizons文档采用ITRF93、修正的IAU1976/1980及其legacy EOP；现代JPL/IERS备选模式与之约定不同。

地球自转数据冻结在明确标注的日期。未来闰秒与新的测量数据需要更新。
所有来源、哈希、实测差异及未解决项见网站的“验证报告”和 data/provenance.json。
保留 vendor/ 中的ERFA许可。DE441数据来源于NASA/JPL公开发布。

## 验证

运行 node tests/full-domain.cjs、node tests/legacy-tests.cjs、node tests/spk-boundaries.cjs，再运行 python3 scripts/report.py。
此命令离线重放113,524个原生ERFA/jplephem参考案例和42,200个已缓存Horizons案例，包含：

- 每日覆盖20,044天；所有所选SPK分段边界的58,440个邻域点。
- 32,768个固定随机种子的独立样本，224个输入角点，2,048个人工EOP极值压力样本。
- 40个全球、近极、经度边界、高度边界和随机保留地点，各1,055个历史/预测/未来时刻。
- 无效输入、日期边界、±180°等价性、所有数据内闰秒事件、外推必须显式启用等检查。

有限测试不能穷尽连续输入空间，也不是全域误差上界证明。
接近两极时子午面病态，极移与参考框架的微小差别会被放大到秒、分钟甚至更大；页面明确警示。
同模型的原生库一致性验证只检查数值实现，不能证明模型等于物理真值。

- tests/generate-native-domain.py 使用 numpy、pyerfa、jplephem 重新生成原生参考。
- tests/capture-domain.py 仅供维护者重新采集对照：串行、批量、缓存的人工坐标查询，不属于网页运行路径。
- scripts/report.py 重建可读报告，不会生成压缩下载包。

## PCK恢复快照与验证

公开ASCII镜像仍是11月17日；精确11月18日原件未下载到。
从官方 earth_000101_270214_261118.bpc 独立恢复2026-10-01至2027-02-14的137条日记录，其余历史记录保留原始11月17日文件。
恢复仅使用PCK旋转矩阵，不用Horizons太阳时残差拟合；随后才用独立Horizons输出验证。

- 70个重叠窗口，零记录冲突；已知历史32条/160个字段按原精度恢复全部一致。
- 544个未参与恢复的PCK时刻检查。
- 42,200组独立Horizons对照：全体最大差异约3.082微秒，含近极区、预测和固定末值外推。
- 32个末端检查：最大差异约0.625微秒。2月14日记录保留作插值支撑，但2月13日起固定参数。
- 每种模型各113,524组独立原生库参考检查；52,596组星历记录边界检查。

这不是原始文件的下载副本，也不是全域误差上界或未来实际地球自转精度的证明。

复现数值检查：

    node tests/full-domain.cjs
    node tests/legacy-tests.cjs
    node tests/legacy-tests.cjs --reconstructed
    node tests/reconstruction-tests.cjs
    node tests/spk-boundaries.cjs
    python3 scripts/report.py

恢复数据的独立复现：先在虚拟环境安装 numpy、pyerfa、jplephem、skyfield、certifi，再运行 research/pck/reproduce.py。
该脚本仅下载固定哈希的官方PCK文件，不调用Horizons；生成物写入被Git忽略的scratch目录。

来源、校验值、失败的单窗口边界诊断和最终重叠窗口验证均保存在数据与测试记录中。
